# Leads module

Purpose: own Workspace Lead inquiry lifecycle and the canonical P1A manual intake transaction.

- Public entry: `index.ts`.
- Owns: `leads`, `lead_lifecycle_definitions`, `lead_intakes`, `lead_activities`, `lead_visible_teams`, and P1A reads of `pipeline_stages`.
- Public operations: `submitLeadInquiryV1`, legacy manual compatibility translation, `listLeadSummariesV1` (`listLeadSummaries.v1`), `getLeadDetailV1` (`getLeadDetail.v1`), `listLeadPipelineStagesV1` (`listLeadPipelineStages.v1`), `getIdentityReviewDetailV1`, `listIdentityReviewQueueV1`, and `decideLeadIdentityReviewV1` for explicit Hold/Resolve.
- Consumes: Contacts, Companies, and Identity Review public transaction participants; Platform tenancy/authorization, database, idempotency, Audit, and Outbox ports.
- Intake write trace: route -> public command -> non-locking trust lookup -> idempotency/intake -> Lead -> Company key -> all candidate/probable Company rows in UUID order + recheck -> Contact key -> all selected Contact rows in UUID order + exact shared-cap recheck -> Platform assignment/visibility references -> immediate actor/assignment/candidate revalidation -> review/head + one governing Audit + exact events -> commit/result.
- Decision write trace: route -> public command -> idempotency -> Leads-owned intake/Lead locks -> Identity Review review/head locks -> declared link snapshot check -> Company key/rows/recheck -> Contact key/rows/recheck -> assignment/visibility locks -> immediate permission, Lead/intake/review/head/target/candidate revalidation with no later identity locks -> atomic Hold or Resolve mutation + one governing Audit + exact events.
- Candidate read trace: authenticated route -> Leads public query -> preview authorization -> Lead/intake and review/head locks -> Company then Contact target locks/freshness -> assignment/visibility locks -> full Workspace/User/Session/Role/Membership and version revalidation -> strict masked allowlist (at most 10 per class/30 total) -> private/no-store response. Authority loss/resolution fails closed; candidate-only drift returns the zero-detail stale envelope. Exact indexed lookups and protected operation target p95 below 200 ms.
- Queue read trace: authenticated route -> Leads public query -> Identity Review Workspace/state/update/id index-backed pending-reference page -> Leads-owned bounded Lead/intake locks -> review locks -> Company then Contact target locks -> one globally sorted page-level assignment/visibility lock participant -> full active-actor/per-row authority, pending, version, and freshness revalidation -> strict safe rows/cursor -> private/no-store response. Page target p95 below 200 ms.
- Lead read trace: authenticated thin route -> active Platform actor -> one tenant-scoped Leads projection containing the Platform-owned reviewed visibility predicate -> a separate current read transaction revalidates active Workspace/User/Session/Membership/Role plus every returned Lead version, assignment, Team visibility and disclosure fact, and re-fetches active Company/assignment presentation through public participants -> capabilities are derived from that fresh actor -> strict masked DTO -> private/no-store response. List returns at most 50 plus one internal `hasMore` sentinel and uses an opaque `(updated_at,id)` keyset whose timestamp retains PostgreSQL microsecond precision; detail is read-only and the legacy PATCH path rejects every Lead with canonical intake lineage. Reads write no Audit/outbox records.
- Pipeline-stage read trace: authenticated thin route -> current actor -> Leads-owned active stage registry ordered by `(position,id)` -> final current-actor fence -> strict allowlisted DTO including empty stages -> private/no-store response.
- Phone trace: strict `parsePersonPhoneV2` canonicalizes before the governing transaction; Lead storage, canonical request hash, candidate lookup and later Contact creation share display, E.164, actual calling code, effective country interpretation and `p1a-identity-v2`. Compatible v1/v2 evidence acquires the same stable sorted email/phone/Company advisory namespace, then rechecks candidates after the last lock. Blank/whitespace phone is absent when email is valid. Invalid input returns only typed field paths and creates no durable receipt or business effect.
- Invariants: every accepted command creates one Lead at `new`; Workspace ownership is permanent; hold never mutates identity; no automatic/fuzzy merge.
- Tests: P1A contract, modular boundary, PostgreSQL transaction/replay/concurrency/rollback/privacy, and route suites.
- Deferred: CSV/XLSX, web/public adapters, conversion, routing, merge, expanded CRM workspaces.
